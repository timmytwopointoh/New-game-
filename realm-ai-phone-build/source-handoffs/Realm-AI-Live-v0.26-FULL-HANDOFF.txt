3. WHAT THE APP CURRENTLY CONTAINS
=================================
A. Phone-hosted Bedrock client and connection
- The bot runs on the Android phone in the app's isolated agent process.
- Uses a separate invited Microsoft/Xbox account to join a Minecraft Bedrock Realm.
- Existing resource-pack negotiation/download fixes and verified cached packs.
- Saved Microsoft sessions and manual rejoin without deleting login files.
- Microsoft device-code display, Copy sign-in code and official clickable link.
- Realm selection by configured identity/name/ID; does not blindly pick the first
  Realm when the account belongs to several.
- Local controller/API binds to loopback and requires an authentication token.
  It is not a public remote-control server.
- Transient Realm join retries are bounded; do not create login-refresh loops.

B. Keep the Nintendo Switch login profile
- authTitle: 00000000441cc96b (MinecraftNintendoSwitch)
- deviceType: Nintendo
- DeviceOS: 12
- flow: live
- Persistent Switch authentication folder: private/auth/switch
- Old Android auth files were retained, not deleted.
- Android-only Sisu title recovery is disabled for the Switch profile.
- Xbox-named service stages are normal for Bedrock authentication, including
  Switch; they do not prove an Xbox-console client identity.
- A reproduced seconds-versus-milliseconds OAuth expiry bug is corrected by an
  adapter without indiscriminately forcing Microsoft reauthentication.
- Authentication identity and movement input are separate. Movement uses touch
  input; the restored Switch title does not imply the bot teleports or needs
  Xbox-console control emulation.

C. Game mode and ability verification
- Tracks this bot's own server-reported mode/abilities, not other players' modes.
- World default is used only for the player's explicit inherit/fallback value.
- Loading-screen protection, permission to fly and actual active flight are
  treated separately.
- Survival work requires suitable effective server abilities.
- Creative is intentionally supported for owner-authorized testing. Normal
  Creative damage immunity/instant-build permissions are not mistaken for a
  reason to forbid grounded walking.
- Active flight/noclip/editor-like movement prevents ordinary grounded jobs.
- Mode buttons send normal Minecraft /gamemode survival @s or
  /gamemode creative @s only when sufficient server permission is reported.
- No automatic granting of operator privileges, enabling global cheats or
  changing global Realm settings.
- Requests wait for actual mode/ability confirmation. Duplicate requests and
  denied/unconfirmed responses are handled without inventing success.

D. Flight removal, gravity and ground contact
- Sends Bedrock EndLoadingScreen after actual nearby terrain arrives, including
  the matching loading-screen ID for dimension transitions.
- Requests flying=false and sends normal stop-flying action/input.
- At most five requests at one-second intervals per flight episode; waits for
  this player's server abilities to confirm flight off.
- Continuous gravity runs after spawning, while idle and after Stop/cancellation.
- Received collision shapes determine clearance, landing and ground contact.
- Handles thin snow and partial-height support/slabs in the physics/path checks.
- Does not treat unknown terrain as air or a floor. Requests terrain; existing
  five-second unverifiable-terrain handling disconnects while keeping login.
- Reconciles authoritative position feedback, ignores vehicle corrections and
  older-tick corrections, and tracks server movement/jump locks.
- Predicted completion is identified separately from server-confirmed movement.

E. Walking, following and climbing — implemented, still needs live testing
- Bounded observed-terrain pathfinding; ordinary walk/follow do not dig.
- Ordinary walking and following can plan one-block jumps/drops with clearance.
- Jumping uses normal input and a physical trajectory, not a teleport command.
- Follow tracks observed players or the configured owner, replans and reports
  waiting/blocked rather than claiming a route exists when it does not.
- Server-feedback stuck detection, detours, bounded recovery and low-health stop.
- Travel requests are bounded to nearby coordinates, normally within 48 blocks.
- v0.26 may plan a small supported dirt staircase when a normal route fails.
  Local rise is bounded to four blocks; it is not unlimited pillaring/bridging.
- Requires known dirt in the hotbar and safe observed support/headroom.
- Each step must receive a server block update and, in Survival, inventory
  consumption confirmation before the bot jumps onto it.
- Creative still requires an actual known held dirt block; it does not invent
  inventory. The held block is not consumed in Creative.
- Stop cancels unfinished placement/jump intent; gravity continues and already
  confirmed dirt stays in the world.
- IMPORTANT: because live placement is unfinished, live dirt climbing cannot be
  considered working simply because its simulated test passes.

F. Mining — implemented but live reliability remains open
- Explicit dig-one-block and bounded clear-path mining requests.
- Uses actual selected hotbar item, reach, visibility, harvest suitability,
  hardness, effects/enchantments where available, and protection checks.
- Holds start/continue mining input across ticks; uses estimated time appropriate
  to the held item. A suitable tool is faster; hand/ineffective-tool mining is slower.
- Supports server-authoritative breaking in auth input and a legacy player-action
  path where the server reports that mode.
- Sends one completion transaction and continues holding while awaiting the
  server block update; Stop sends abort/release.
- A server update to air confirms removal; it does NOT prove item collection.
- Stops on changed tool, reach/protection failures, target changes or timeout.
- The current assessment has a bounded mining-time budget (default about five
  seconds estimated work), plus a confirmation timeout. It is not unlimited
  bare-hand mining of every hard block.
- Explicit dig checks include safe standing position and restrictions on underfoot
  or overhead mining. Recovery clearing is conservative and limited.
- Ordinary walk/follow never decide to mine player structures to get through.
- Earlier phone attempts failed to get server-confirmed breaks. No later evidence
  establishes that all mining targets/tools now work on the live Realm.

G. Building/placement — UNFINISHED ON THE PHONE
- Source contains real item-use placement transactions for a block, wall, floor
  and fixed shelter, separately from supply/build previews.
- Intended to check actual hotbar supplies, suitable simple full solid materials,
  known-air targets, a visible/reachable support face, safe approach and protection.
- Waits for block updates and Survival inventory consumption. Creative should use
  the held material without decrementing its count.
- Explicit wall: width 1-6, height 1-3. Floor: dimensions 1-6 by 1-6.
- Fixed shelter: 5 x 5, floor, three-block walls, roof, two-block doorway; 96 blocks.
- Existing blocks are not replaced automatically. Partial/oriented/interactive,
  falling and hazardous block placement is not generally supported.
- Stop leaves already confirmed placements in place and cancels the remainder.
- These are implemented paths/simulated tests, not a completed live building
  feature. The owner's latest report takes precedence: placement is not ready.
- Some older preview/help messages still say placement is not implemented at all,
  although explicit placement paths exist. Wording needs reconciliation after
  the underlying live behavior is established. Do not silently treat previews
  as successful world edits.

H. Inventory, terrain and catalog
- Observed inventory counts, selected hotbar slot, known held-item information.
- Hotbar selection is 1-9 and based on actual received inventory.
- Chunk/subchunk decoding, block updates, nearby scans and visible-block lookup.
- Find locates visible nearby matching blocks; it does not automatically gather.
- Searchable block/material catalog, about/material information and recipe data.
- Supply planning and wall/floor/shelter supply previews.
- Preview quantities 1-256; preview dimensions up to 12, distinct from the smaller
  executable placement limits above.
- Recipes/supply planning do not perform crafting, smelting or automatic gathering.

I. Plans, queue, Stop and conversation UI
- Shared command catalog drives popup forms and validation.
- Up to FIVE saved commands/plans, stored privately and scoped to the Realm.
- Tapping/preparing a command saves it and selects it for the next activation.
- Preparation alone does not start work; fields are checked again on activation.
- Reusable completed cards, selection, deletion and Reuse controls are present.
- The final UI uses selected-first activation of waiting queued work. This
  superseded the earlier selected-only design; do not revert it accidentally.
- One active job at a time, with roughly two seconds between completed queue items.
- Duplicate activation/taps and delayed requests from before Stop are guarded.
- Saved descriptors survive restarts without automatically resuming work.
- STOP cancels work immediately through the urgent path; it does not turn off
  gravity. Stop bot service is a separate control in Settings/power handling.
- Main screen: power indicator/control, Updates, Settings, progress/connection
  text, chat, STOP, central green Activate, Commands and prompt/send controls.
- Account, mode, saved-plan management, learning and diagnostics remain in Settings.
- The word 'command' opens command options. 'command <action>' prepares an action.
  Questions/plain sentences are treated as conversation/read-only requests rather
  than arbitrary execution. Stop remains immediate.
- Ordinary chat, greetings, jokes/teasing and clarification are supported by rules.
  This is not unrestricted language understanding.

J. Language and memory
- The merged Live source includes the other app's offline 5,000-word glossary,
  attribution, definitions/context and Minecraft terms/action synonyms.
- Learns owner-confirmed action/material word mappings privately per Realm, up to
  200 mappings; review/forget controls are included.
- Unknown/ambiguous action words can ask what was meant or offer a confirmation
  before learning a supported mapping and preparing a command.
- Distinguishes heights/dimensions and stacks/quantities in supported parsing;
  unclear slab/build requests ask for clarification.
- Remembers task outcomes as confirmed, blocked, interrupted/unverified and can
  remind the user to recheck a previous failure. This is not proof of a repair.
- There is NO bundled neural language model, autonomous model training, arbitrary
  code rewriting or general-purpose internet search in this build.
- It cannot reliably turn every unfamiliar sentence into a Minecraft action.
  Word learning maps to implemented actions; it does not create new abilities.

K. Death and respawn — new in v0.26, not phone-confirmed yet
- Responds to this player's server health/death/respawn information.
- Interrupts active work and queued execution on death.
- Sends normal Respawn action, acknowledges server-ready position with client
  ready state, then waits for positive server health.
- Does not set health locally or use Creative/invulnerability to fake survival.
- Bounded retries, a roughly 15-second confirmation timeout and Hardcore handling.
- Previous jobs remain stopped after respawn and loading.
- A parameterless Respawn command supports a manual retry when actually dead.
- This does not add fighting, eating, armor use or smart zombie avoidance. The
  bot can still be attacked and killed; low-health stopping is not self-defense.

L. Bug reports, file access and signed updates
- Settings -> Bug reports -> Export ZIP. Also reachable from Updates.
- Export works without a running bot/API, using Android's document save picker.
- Report includes recent sampled game state, in-game coordinates, terrain/mode/
  flight/ground state, death/respawn, packet counters, grouped symptoms, safe
  source-frame locations and Android/service/updater event codes.
- Bounded private histories: up to 240 runtime events and 200 Android events;
  grouped issues are diagnostic clues, not automatically proven root causes.
- Raw packets, account names, chat, Microsoft codes/tokens/passwords, private
  signing material and unrelated phone files are excluded.
- Missing/malformed reports still permit an app-only export.
- 'Share one file' opens Android's picker/share sheet for only the selected file.
- Neither export nor sharing gives this chat live access to the phone filesystem.
- No automatic upload, remote shell, hidden remote editor or live pairing exists.
- Practical repair loop: reproduce -> export ZIP -> attach here -> investigate ->
  make/test source fix -> publish signed update -> user installs/tests.
- Updater checks a signed release notice, verifies package/version/hash/size and
  the same signing certificate, then stages the APK privately over HTTPS.
- Notifications/checks can run while the bot service runs; downloads leave the
  bot running. Installation restarts/disconnects it and Android asks for approval.
- Installation does not automatically restart old jobs. Saved sessions/plans are
  retained by normal same-package/same-key higher-version updates.
- Feed: https://raw.githubusercontent.com/timmytwopointoh/New-game-/realm-live-update-channel/release.json
- Update checks/download/verification/install outcomes are logged in v0.26.
- v0.26 feed/public download were verified after publication. End-to-end install
  behavior on the owner's actual phone still needs confirmation.
