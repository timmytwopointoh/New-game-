# Realm AI Live v0.37 — survival workflows TEST BUILD

Frozen at the owner's request on November 1, 2026. Package `com.veilforge.realmagent.live`, versionCode **200018**, versionName `0.37-survival-workflows`. Install over the existing same-key Live app. Saved Microsoft sessions, plans and private data remain in the app; no replacement signing key or authentication profile was created.

## Implemented code in this snapshot
- **Respawn:** reacts to own death-animation/death-screen packets as well as health zero. Sends normal Respawn action and ClientReadyToSpawn, accepts the server's own/zero-ID ready response after death, and does not mistake stale pre-death positive health for recovery. Fresh server health confirms recovery. Hardcore/denied/time-limited states stay stopped. Interrupted tasks never automatically resume after death.
- **Situation:** own healthy/hurt/dead state, server position, relative observed mobs/blocks, medium and server-sourced biome data. Missing biome data stays unknown. Biomes are retained for full chunks and subchunk-request-mode chunk headers; bounded private Realm memory records observed materials/biomes and rechecks locations rather than treating memory as live proof.
- **Hazards:** water/lava/powder-snow escape attempts use ordinary jump/swim/movement inputs. Normal routes still reject lava and unsafe/unknown terrain. Lava never becomes safe or grants fire immunity. Thin snow and partial-block collision fixes remain. Escape can fail; damage/death and server corrections remain authoritative.
- **Dirt climbing:** existing stairs/bridges plus jump-place pillars, bounded to short rises. Server-reported height must clear the proposed support before placement. Actual block and Survival consumption confirmation precede counting a support. Dirt in backpack can be moved/swapped into the hotbar without discarding tools; missing dirt can trigger shovel/64-dirt preparation before resuming the explicitly requested follow. Stop cancels intent while gravity continues.
- **Strip mine:** configurable 1–16 legs (default 8), 30 cells per leg, two high, Y -20 by default, four-block lateral connectors. Alternating return turns advance into fresh lanes rather than re-entering the first tunnel. Descent is a staircase with head clearance, never a shaft dug under the bot. Actual tools and 64 dirt are checked first. Reachable ores may be collected opportunistically; protected/unsafe ores are skipped. Each ordinary mined drop and each movement step needs server evidence. The end-stage prepares double-chest storage; two chest blocks alone do not prove a merged double chest.
- **Mine dirt / quarry:** 15×15 areas, two blocks deep. In Survival it continues into adjacent areas until 640 requested items are actually in inventory, as confirmed by the owner. Ten partially occupied slots do not satisfy the threshold. Storage uses the second confirmed tree site, a crafting table and an owned chest. A latched deposit drains the selected resource even after the remaining inventory falls below 640. Creative excavation finishes a patch without inventing Survival drops or a 640-item deposit.
- **Crafting/furnaces/transfers:** received recipe IDs, real source stack IDs, bounded requests, matching server replies/snapshots, owned station/chest placement, container-open/content checks, furnace input/fuel/output and hotbar swaps. Failed/late replies cannot invent items or credit a different chest reusing a window ID. Creative supplies can be taken only from the received server Creative catalog while this player's Creative mode/abilities are verified, and still need server inventory confirmation.
- **Acquisition:** shared quantity/material commands prepare prerequisites, re-scan remembered sources, roam through observed terrain when sources are absent and resume search after depletion. Tool upgrades can request actual crafting/smelting. Mining/crafting, inventory, construction and travel remain mutually controlled; Stop interrupts the parent and its children.
- **Dimensions:** material/dimension prerequisites, active-portal preference, existing-frame ignition, supported full Nether-frame construction with actual obsidian/dirt scaffolding, Eye-of-Ender signal search, received End-frame eye filling, and normal portal-entry inputs. A server dimension-change packet is required for success. Dragon evidence is tracked; absence is not defeat. End-city/elytra work is gated when dragon status is unknown/alive.
- **UI:** Strip mine, Quarry, Gather, Craft and Situation commands are in the command rail. Existing Microsoft link/code/Copy, signed updater, private reports, saved plans, chat and immediate Stop are retained.

## Validation
357 Node tests and 47 Android tests passed. They include real Bedrock serializers and simulated independent server events, phone-sized native menu/layout checks, death/health races, recipe and container evidence, furnace flow, full hotbar swaps, chunk-biome parsing, mining geometry, pillars, hazards, frame construction/ignition, End sockets and late-window isolation. APK source parity checks covered 71 shipped runtime/tool/template files. Native libraries and dependencies are byte-identical to the verified v0.36 baseline. Package/version, signing certificate, archive integrity and 16-KiB alignment were checked. Public recipe reconstructs the exact locally signed APK.

**No live Realm test or physical phone installation happened in this session.** Passing simulated tests is not proof that BDS accepts every new crafting, furnace, container or portal sequence.

## Important remaining work / limits
- Test respawn first, then one craft/placement/transfer and a short mining run before a long autonomous mission. Export Settings → Bug reports if anything is denied or stuck.
- Full autonomous dragon combat, End-city loot retrieval, arbitrary mob-loot/trading, enchanting/Silk Touch provisioning and every exotic recipe are NOT complete. Unsupported prerequisites pause with an explanation; recognizing a material is not proof the bot can obtain it.
- Full-tree crown felling and the older continuous forestry/chest-retrieval cycle are still incomplete. A registered tree site/trunk is not a fully felled tree.
- Portal/stronghold controls and water/powder/lava escapes are experimental and require live verification. They cannot promise to solve every terrain arrangement or survive lava.
- Minecraft does not expose reliable player-placement provenance. Ordinary dirt/stone builds cannot always be distinguished from natural terrain. Known/likely builds and containers remain protected.
- Normal drops, special harvesting requirements, NBT/tool durability variants and rare resource sources need further field validation. No item, health, portal or task completion is fabricated to hide an unsupported case.
- There is no remote phone-file access, autonomous source-code rewriting or trained neural model. The app has a local vocabulary/planner, private observation memory and user-exported diagnostic ZIPs.
